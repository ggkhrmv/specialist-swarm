How it's built

A coordinator briefs four specialists in parallel in one shared container

Skills are markdown files: change a rule, re-run setup3 / 9
Everything runs in one Managed Agents session. The partner, on Opus, reads the RFP and briefs four specialists in the same turn. Each specialist has a narrow prompt and its own playbook as a skill, and reads the same mounted files. They don't see each other's work, so nobody anchors on anybody. The partner cross-checks the reports, then writes the docx and the deck. The firm's rules live in markdown skills, not code.

How four people shipped it in a day

One worktree per change, one swarm per worktree, a $0 gate on every PR

  • Worktrees: claude -w you-topic. A hook blocks edits on main, so nobody steps on the demo.
  • Isolated cloud state: each worktree owns its own agents, so one person's prompt experiment never changes anyone else's run.
  • Prompts and playbooks are files: four lanes edit four files, with no merge conflicts in code.
  • $0 gate: tests/offline_check.py runs the whole pipeline against a fake client in CI, including every eval case.
  • Stretch goals shipped: Critic (S2), memory across deals (S3), fan-out timing (S4), a synthetic CRM MCP server (S5), pitch deck (S7), evals.
